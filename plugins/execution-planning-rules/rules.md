## 階段開始前，先評估執行方式

開始一個研究、需要寫規格或計畫、或要開始執行之前，先分別為「制定計畫」和「執行」評估下列四項。用表格列給使用者，每項附建議與一句理由，由使用者決定後再開始該階段。

| 項目 | 要回答的問題 |
|---|---|
| 地點 | 開新 session（新視窗），還是在目前這個做 |
| 模型與邏輯強度 | 用哪個模型、哪個 effort，fast mode 開或關 |
| 協作方式 | 只在主 session 做，還是派子代理協作 |
| 審查方式 | 只在最後整體審查、每個任務都審，或只審高風險任務 |

評估時的依據：

- **先查額度。** 評估前讀一次方案用量（5 小時、每週、各模型的每週額度），快到上限的就避開會用到它的選項。
- **開不開新 session。** 下一階段已有規格或計畫檔能接手時就開新的，並在評估裡附上目前 session 的 context 用量。長 session 每輪都重讀整段對話，越長越貴，而檔案已經帶著所有決定。
- **主 session 或子代理，依成本效益判斷，不預設用子代理。** 2026-10-16 的實驗：同一份寫好介面與測試的計畫，子代理逐任務約用了主 session 自己做的 2 倍額度與時間，但每個任務都有獨立審查，合併前就擋下規格遵循的問題。計畫完整時，預設由主 session 用強模型自己做，最後派一個獨立審查者審整條分支；任務真的互不相依，或逐任務審查值得約兩倍成本時，才用子代理。
- **明確指定模型與 effort。** 每次派子代理都要指定，否則會繼承主 session 的設定；建議開新 session 時也直接帶上選定的模型與 effort。
- **把選定的方式寫進計畫檔開頭**，例如「執行：主 session 自己做，Opus high，最後一次 Opus 審查」，讓新 session 接手或 context 壓縮後照著做。
- **量測平常從簡。** 一般只記開始與結束時的額度；逐任務記錄只在比較執行方式的實驗時做。

評估表的樣子，每格接一句理由，最後一行寫建議：

| 階段 | 地點 | 模型與強度 | 協作方式 | 審查方式 |
|---|---|---|---|---|
| 制定計畫 | 目前 session：context 用了 40%，前面的討論都還要用 | Opus high：規格要寫得精準 | 主 session：一份文件，不值得派子代理 | 不另審：使用者會讀過 |
| 執行 | 開新 session：計畫檔已帶著所有決定 | Opus high | 主 session 自己做：計畫已寫好測試與介面 | 最後一次整體審查 |

## 列出選項或決定時用表格

列出可選的選項、已做的決定或裁定、或要使用者分流的審查結果時，用表格：每列一個選項或決定，欄位寫它是什麼和理由（或好處與代價），並標出建議的那一個。每格約一句話，較長的說明放在表格下方，最後給建議或問題。單一論點或一段推理仍用一般段落。
